# 质量与可执行性评估

对已有用例先通读，再按六项准则评估质量并统一评估可执行性；评分对象始终为当前文档，不修改用例，也不将修改建议计入当前分数。需求基准用于核对覆盖和预期依据；仅有局部评审范围时，不输出整份文档的汇总或质量结论。

## 质量评估

默认直接采用以下六项准则，不实时查询或核验国际标准。只有当前任务明确要求依据国际标准，或需要补充理解测试文档、测试技术以及测试设计与实现的过程边界时，才按需参考 `ISO/IEC/IEEE 29119` 系列；国际标准只作为质量评估参考，不作为认证或符合性结论的依据。

1. **范围覆盖**：范围和需求基准明确，范围内的重要行为有用例或未覆盖说明。
2. **要素完整**：用例有唯一编号、明确目标、优先级、前置条件、测试数据、步骤和预期结果。
3. **可复现**：条件、关键输入和操作顺序足以让具备系统基本知识的执行者复现。
4. **可判定**：预期结果可观察、有需求依据，并能判断通过或失败。
5. **一致且最小充分**：用例之间无明显矛盾、无目的重复，覆盖方式与用户确认的范围一致。
6. **技术适用**：根据需求实际存在的条件组合、边界、状态变化或业务流程选择适合的测试设计方式，不机械套用全部技术。

为整套用例给出一个结论：

- `达标`：六项全部满足，没有影响重要需求验证的缺口。
- `有条件达标`：不存在影响核心验证的问题，但仍有局部缺口或执行限制。
- `不达标`：范围内的重要行为缺少覆盖说明；核心用例缺少对象、动作，或者缺少有充分依据且唯一明确的预期；资料中存在会改变判断结果的矛盾。

对话中给出各质量项的判断依据、问题和限制；资料不足时注明无法判断，不猜测缺失内容，不输出认证声明。经确认沉淀时使用既有报告字段。

## 可执行性评分

分数使用 10% 的整数倍。

### 操作明确度

每个适用维度取 `0`、`1` 或 `2`：`0` 表示缺失、存在歧义或无法从现有资料判断，`1` 表示业务含义明确，`2` 表示具体名称、数值或位置明确。与用例类型无关的维度记为 `N/A`。

| 维度 | 评估内容 |
| --- | --- |
| 对象与入口 | 被测功能、页面或业务对象是否明确 |
| 操作控件 | 主要动作、字段、按钮或选项是否明确 |
| 输入数据 | 关键值、数量、状态和对象关系是否明确 |
| 操作顺序 | 主要步骤和必要分支是否明确 |
| 结果观察 | 检查对象、字段、状态和关联结果是否明确 |

`操作明确度 = 适用维度得分之和 ÷（适用维度数量 × 2）× 100%`，结果四舍五入到 `10%` 的整数倍。

- `0%～39%`：不足以形成正式执行用例。
- `40%～59%`：偏语义化，需要较多产品理解。
- `60%～79%`：基本明确，熟悉系统即可执行。
- `80%～100%`：高度明确，基本可以直接执行。

默认目标不低于 `60%`。测试对象、主要动作或唯一预期结果缺失时，无论总分多少都不能认定为可执行用例。低分时指出缺失或歧义及修改建议，不实际细化或修订用例。

### 执行准备难度

执行准备难度只衡量执行该用例需要准备哪些条件以及准备工作的复杂程度，不要求先核实真实环境是否已经具备这些条件。根据用例本身描述的角色、数据、协作方式、工具和观察方式，逐项判断属于常规准备、专门准备还是复杂准备；不计算分数，也不使用平均值抵消单项难点。

| 维度 | 常规准备 | 专门准备 | 复杂准备 |
| --- | --- | --- | --- |
| 账号与权限 | 普通测试账号 | 特定角色或权限 | 多角色配合或特殊授权 |
| 数据与状态 | 常规业务数据 | 特定关联数据或状态 | 多对象关联、罕见状态或较长数据链路 |
| 协同操作 | 单人、单系统 | 多账号或多会话 | 跨系统协作或需要严格控制同时操作的时机 |
| 所需工具 | 页面即可完成 | 需要接口或日志工具 | 需要模拟异常或使用专用工具 |
| 结果观察 | 页面即可判断 | 需要接口或日志辅助 | 需要检查多个系统或难以直接观察的内部结果 |

综合五个维度，按以下启发式规则确定最终等级：

- `低`：各维度均为常规准备，或只有一个维度需要专门准备，且可以通过常用手段完成。
- `中`：两个以上维度需要专门准备，或有一个非关键维度属于复杂准备，例如多角色配合、特殊授权或复杂关联数据。
- `高`：需要跨系统协作、严格控制同时操作的时机、使用专用工具模拟异常，或结果难以直接观察；两个以上维度属于复杂准备，或多个准备条件相互依赖时，也判为高。

介于两个等级之间时采用较高等级，并在“主要限制或准备要求”中说明决定因素。只按用例要求判断准备难度；未核实真实环境是否具备账号、数据或工具，不应把整条用例记为“未知”。如果用例本身没有说明执行所需的关键条件，应按实际缺失评分，并在对话中指出待确认事项，不修改用例正文。

## 输出要求

评估范围内全部用例，对话中汇总（局部范围必须注明）：

- 平均操作明确度及低于 `60%` 的数量；
- 执行准备难度为低、中、高的用例数量。

需关注用例默认列出操作明确度低于 `60%` 或执行准备难度为“高”的用例，说明限制或准备要求；其他质量问题仍须进入对话问题清单，不能因分数高而省略。用户要求完整明细时列出全部用例。

平均操作明确度为范围内可评分用例百分比的算术平均；某条用例无适用维度时注明无法评分，不以零值代替，并披露未计入汇总的数量。存在无法评分用例时，汇总标明不完整，不作为全量结果保存。

操作明确度百分比和执行准备难度分级用于同一份文档内部比较，不是测试已经执行或环境已经就绪的证明。
